# NAVSIM 能力阶梯：基于联网检索的论文完善计划

日期：2026-10-09。定位：分析型研究；以下是待验证假设和实验设计，不是已经取得的结论。此次检索覆盖官方基准、相近论文和编码方法，不能证明穷尽全部相关工作。

## 1. 重新确定问题

建议主问题：**动态障碍物信息在什么条件下改善模仿学习规划，为什么相同信息在某些模型里产生负收益？**

现有 navtest 三种子结果：ego-only pose MLP 0.642，增加障碍物 0.659，增加地图 0.823，地图和障碍物同时输入 0.782。按 log 聚类后，地图条件下障碍物的平均效应为 -0.0407，95% CI [-0.0575, -0.0249]。这是需要解释的现象。原来的输入同时包含最近八个框和前车 gap/speed，不能把全部效果归因于检测框本身。

三个竞争解释：

- H1 表示与优化：排序后直接拼接不利于提取交互信息，零填充、归一化或容量分配也可能导致退化。
- H2 数据需求：更复杂输入在小数据量/有限训练预算下难学，扩大数据或训练后效应改变。
- H3 评测与场景构成：总体均值掩盖了跟车、横穿等场景的收益；日志中的自车状态可能已经包含人类对障碍物的反应。

三个解释可以同时成立。现阶段不预设应验证哪一个。

## 3. P0：先完成可信度审计

交付：`audit.json`、明确的版本标识和失败/回退清单。

1. 区分 invalid scoring、模型异常、无路径回退、非有限输出、路径端点裁剪。逐 token 记录原因；旧评分中“valid=True”不能替代这项记录。
2. ego-only pose 模型直接使用 AgentInput 的自车特征，不因地图不可用而改变推理路径。规则路径 ds 模型即使速度网络没有地图输入，最终轨迹仍使用地图，必须标记为 privileged。
3. 将框和速度坐标约定与 OpenScene/NAVSIM 上游构造代码对齐；做已知旋转、静态障碍物、相对/绝对速度、空框、多框排序的数值检查，再人工核对真实场景。
4. 对训练/推理特征做数值一致性检查；核对标准化只使用训练数据、零填充 mask 正确、没有读取 future annotations 作为输入。
5. 保留旧 checkpoint 与逐场景 CSV。修复后的代理、缓存和新结果使用新版本目录，先用旧模型检查执行语义变化；必要时重建特征并重训。
6. 确认偏航角、位移、arc-length 的单位和损失定义。当前 pose L1 混合 m/rad，不能与 ds 的 m 损失直接比较。

通过条件：异常都能定位，正常样本的训练/推理特征一致，盲模型路径与地图解耦，所有回退均被披露。若发现实质数据错误，优先修复并重评原 2x2，再开展新实验。

## 4. P1：最小机制实验

固定：ego + 中心线输入、pose 输出、同一训练/验证 log 划分、相同 checkpoint 选择政策。新增六组，每组三个配对训练种子，共 18 个模型。

| 编号 | 动态信息/编码 | 要回答的问题 |
|---|---|---|
| M0 | 只用 ego + map；动态分支禁用/置零 | 新实现下的锚点 |
| M1 | 真实八框，排序拼接；独立前车特征置零 | 不混入前车工程特征的框信息效果 |
| M2 | 条件匹配的跨 log 框置换，拼接；前车特征置零 | 额外维度/分布与当前场景对齐信息的区别 |
| M3 | 只加前车 gap + speed；框置零 | 简单低维交互摘要是否更有效 |
| M4 | 真实八框，masked Deep Sets；前车特征置零 | 集合编码能否消除/减少负收益 |
| M5 | 同 M2 的框置换，masked Deep Sets | 编码改善是否确实利用场景对齐信息 |

M2/M5 的 donor 来自本 split 的不同 log，在速度、转向和对象数分箱内匹配；验证/测试不从训练或其他 split 混入 donor。保存固定 donor 映射及匹配覆盖率，不用未来轨迹匹配。它仍是破坏场景一致性的负对照，不是物理反事实。

另做同场景对象顺序置换：这保留对象集合，主要检查顺序依赖。它与跨场景置换回答不同问题。测试时遮挡/删框仅作分布外敏感性诊断，不代替从头训练的消融。

控制参数量（目标差距在 10% 内，做不到就披露并加容量对照）、更新步数、batch、归一化和训练搜索预算，报告真实参数量、收敛曲线、CPU 推理耗时。M0 与有对象的模型有效参数不同，因此性能变化不能仅由一个总参数量数字解释。

先 Deep Sets，再视结果决定是否加小型 attention encoder。采用成熟编码器的改善是机制证据，不是方法新颖性的充分条件。

## 5. P2：学习曲线和场景分析

学习曲线只选 M1/M4：10%、30%、100% 训练 log，三个种子。较小集合严格嵌套，验证 log 不变；100% 复用 P1，新增 12 个模型。主要比较固定更新预算，补充相同 epoch 的敏感性检查，避免把更多优化步误认为更多数据的效果。

分层由当前可观测输入定义，阈值在 navtrain-val 确定并冻结：

- 无近邻物体 / 有近邻物体；
- 低速/中高速；直行/转弯；
- 路径走廊内近距离前车；
- 当前速度外推显示与规划走廊可能相交的横向交通。

用未来标注才能确认的“真实 cut-in”等只能作为额外事后诊断。每层都报告场景数、独立 log 数、NC、DAC、TTC、EP、舒适度和 PDMS。小层样本不足时只展示效应与区间，不强行做结论。

输出：一张学习曲线、一张子组效应图、一张安全-进度图，及预先固定抽样规则的失败案例；不能只挑最好/最坏的截图。

## 6. P3：跨协议验证，按资源选择

保留 v1 作为已完成的主分析；核心机制在验证集出现可解释模式后，再移植少量代表模型到 v2 独立环境。

- 官方 v2 支持 log-replay 与 reactive IDM 的单阶段交通；自车仍提交整段计划，不能称为完整交互闭环。[官方 traffic agents 文档](https://github.com/autonomousvision/navsim/blob/main/docs/traffic_agents.md)
- 正式两阶段评估需核对合成状态下地图、对象和自车特征的一致性，并使用独立 v2 cache。不能直接拿 v1 缓存或旧代理拼接后宣称完成迁移。
- 官方文档列 navhard 两阶段 logs 892MB、sensors 31GB；结构化代理能否只依赖日志，需实际冒烟测试，不能预先保证。[官方 splits 文档](https://github.com/autonomousvision/navsim/blob/main/docs/splits.md)
- navhard 来自 test 数据，不能默认它与已经分析过的 navtest 独立；迁移前检查 token、log 及来源关系，把它作为跨协议验证，不伪装成完全未触碰的最终测试。

在本机 16GB 内存条件下，训练、缓存、评测串行；先测单模型吞吐/内存再定并发。大规模传感器模型、CARLA 和全量 nuPlan 闭环扩展不作为首轮依赖。

## 7. 统计、测试集和停止规则

已有 navtest 用于提出新假设，论文应明确这是探索性结果。新架构/阈值只在 navtrain-val 上选择；再从 navtrain 中按完整 log 划出并冻结新的确认集，需要重训以确保从未参加训练/选型。由于已有模型见过这些数据，这仍不等于全项目从未触碰的新外部数据；应披露边界，争取后续外部验证。

主对比预先固定为 M1-M0、M4-M1、M4-M5。逐种子报告效果，再报告配对平均与 log-cluster CI；对这三个主对比报告多重比较处理。log 名可能是同次驾驶的不同切片，补按原始驾驶 session 聚类的敏感性分析。三个种子只能初步刻画训练随机性；关键发现若对种子敏感，扩到五个。

若修复后原负效应消失，写“实现问题导致的消融偏差”，不能保留旧机制故事。若 Deep Sets 没有效果，继续检验训练预算和子组，不为显著性反复试结构。若 18 个核心模型及必要确认实验仍无法分清竞争解释，先交付可复现技术报告，停止扩充模型清单。

## 8. 论文形态和执行顺序

暂定题目：*When Does Dynamic-Object Information Help Imitation-Based Planning? A Controlled Study on NAVSIM*。

正文围绕三个证据：表示方式的受控对照、数据规模依赖、交通场景/评测协议依赖。原能力阶梯作为动机与基线；路径-速度分解作为次要分析；单种子的正则化扫描放附录。

执行顺序：P0 审计 → P1 六组实验 → P2 两条曲线及子组 → 按证据决定 P3。第一轮预算 18 个新模型；通过机制检查后再增加 12 个学习曲线模型。以实测耗时安排工作，不承诺原先“挂着就能次日拿全结果”的时间线。

分析型 workshop/短文是合理的初始写作目标，是否达到具体会议标准要在机制、确认实验和相关工作全文对照完成后判断。当前不能保证录用或主会新颖性。

## 9. 全文核对后的定位补充

现已读完《Driving on Memory》23 页全文及附录，并核对关键图表。
它已经包含 HD-map-only、交通场景分层、表示探针和 v2 评测；这些项目
本身不能作为我们的新颖性声明。保留原实验计划，但论文贡献必须落在
当前对象的场景对齐、编码方式和数据预算的受控交互，而非重复静态信息优势。
具体证据边界见 [全文对照](CLOSEST_PRIOR_REVIEW.md)。该核对不保证穷尽文献，
也不改变以负结果/不确定结果交付技术报告的停止规则。

## 10. 执行中的对照限制与追加规则

在尚未读取完整受控 PDMS 对比前，输入审计显示：现有 donor 在验证集仅
43.7% 同城，其他 split 同城率为 29.6%-42.4%。因此 M1-M2、M4-M5 同时
改变场景一致性和城市分布，不能直接隔离“当前交通交互”的作用。
保留已冻结核心实验，不中途修改其 donor。若论文要依赖场景对齐结论，
必须另行冻结同城、不同原始驾驶 session 的对照，披露无可用 donor 的
城市/分区，并在完全相同的可评测场景上比较。训练队列或归一化若改变，
相应真实输入锚点也必须重训；否则只能将原 donor 结果作为复合干预诊断。

案例抽样和后续资源 gate 见 `results/mechanism_v2/protocol/diagnostics.json`
与 `followup_policy.json`。这些数字规则是在训练启动后、完整 PDMS 对比前
追加的，不伪称原始文字计划已经预定了全部阈值。学习曲线可由正/负效应
触发；种子方向冲突必须追加验证或放弃相关关键结论；跨协议尝试必须先
满足验证与确认结果的一致性要求，且仍需独立环境和实际可行性检查。

## 11. 输入类别表述的进一步限定

源代码筛选 `vehicle`、`pedestrian`、`bicycle`、`generic_object` 四类。
本地上游 `AGENT_TYPES` 不包含 `generic_object`；筛选变量虽叫 `DYNAMIC`，
并不证明全部框都是已识别的运动参与者。车辆/行人各有一个类型标志，
自行车与 generic object 均为两个标志全零，现有输入没有显式区分后二者。
保留冻结特征与实验，论文将对象分支表述为“选定类别的当前对象信息”，
明确其范围；不得把结果推广为完整动态感知或完整交通交互的结论。

## 12. 基础方法与补充材料核对后的重叠说明

PDM 已建立中心线/ego 条件 MLP，并讨论开环拟合与闭环规划的错位。
NAVSIM 原论文及官方补充材料已包含多种输入组合、多个训练比例、
三个种子与子指标分析。因此阶梯、数据曲线或这类图表单独不能作为新贡献。
Deep Sets 是成熟结构；当前有限宽度 mean/max 实现不能援引通用定理
宣称性能保证。上述核对保留原实验和停止规则，进一步要求论文以
场景对齐、编码方式及其受控交互为候选问题，并披露同城对照的覆盖限制。

同城追加设计已在完整核心 PDMS 报告出现之前，以生成器/输入辅助源码
和基础协议哈希绑定到 `results/mechanism_v2/city_protocol/design.json`。
这只证明设计绑定时点；donor 数组生成、训练及评测仍需独立完成。
